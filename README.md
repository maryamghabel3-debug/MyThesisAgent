# 🎓 MyThesisAgent — سیستم خودکار نگارش پایان‌نامه

## معرفی پروژه

این پروژه یک سیستم چندعاملی (Multi-Agent) برای **کمک به نگارش پایان‌نامه کارشناسی ارشد در رشتهٔ روان‌شناسی** است.
در این سیستم چند «عامل» (Agent) با نقش‌های مشخص با هم همکاری می‌کنند:

| عامل | فایل | مسئولیت |
| --- | --- | --- |
| 🧑‍🏫 استاد (Professor) | `agents/professor.py` | ارکستراتور اصلی؛ برنامه‌ریزی فصل‌ها و واگذاری کار به سایر عامل‌ها |
| 🔍 پژوهشگر (Researcher) | `agents/researcher.py` | جست‌وجوی منابع علمی، بررسی ارتباط، اعتبارسنجی DOI و استخراج متادیتا |
| ✍️ نویسنده (Writer) | `agents/writer.py` | نگارش پیش‌نویس بخش‌ها بر اساس منابع و ساختار مصوب |
| 📝 ویراستار (Editor) | `agents/editor.py` | استانداردسازی استنادها (APA7)، انسانی‌سازی متن و خروجی DOCX |

## تنظیم متغیرهای محیطی

1. از روی الگو، یک فایل `.env` بسازید:

   ```bash
   cp .env.example .env
   ```

2. مقادیر واقعی را در `.env` وارد کنید:

   | متغیر | توضیح |
   | --- | --- |
   | `LLM_API_KEY` | کلید API مدل زبانی (الزامی) |
   | `LLM_BASE_URL` | آدرس پایهٔ سرویس سازگار با OpenAI |
   | `LLM_MODEL_NAME` | نام مدل مورد استفاده |
   | `GITHUB_TOKEN` | توکن دسترسی به ریپازیتوری |
   | `GITHUB_REPO` | آدرس ریپازیتوری (صورت `کاربر/نام‌ریپو`) |

> ⚠️ فایل `.env` در `.gitignore` قرار دارد و هرگز کامیت نمی‌شود.
> **هیچ‌وقت** توکن‌ها و کلیدهای واقعی را در هیچ فایل دیگری ننویسید و کامیت نکنید.
> برای اجرای ورک‌فلوی گیت‌هاب، مقادیر `LLM_API_KEY` و `LLM_BASE_URL` باید در
> **Settings → Secrets and variables → Actions** به‌صورت Secret ثبت شوند.

## نحوهٔ اجرا

اجرای محلی:

```bash
# نصب وابستگی‌ها
pip install openai python-docx requests

# اجرای عامل استاد (نقطهٔ ورود سیستم)
python agents/professor.py
```

اجرا از طریق گیت‌هاب:
از تب **Actions** در ریپازیتوری، ورک‌فلوی **Thesis Pipeline** را انتخاب و با دکمهٔ
**Run workflow** اجرا کنید. خروجی پوشهٔ `output/` به‌صورت Artifact ذخیره می‌شود.

## 🔎 The Researcher — راستی‌آزمایی چندمنبعی منابع

ماژول `agents/research_tools.py` به‌همراه خط فرمان `agents/researcher_cli.py`
برای «یافتن، راستی‌آزمایی و ثبت شواهد» منابع علمی بدون اتکا به حافظهٔ مدل ساخته شده است.

- **خط لولهٔ خودکار (انگلیسی):** اولویت با OpenAlex سپس Crossref؛ برای موضوعات
  روان‌شناسی سلامت/زیستی، Europe PMC و PubMed؛ سپس DOAJ. Semantic Scholar فقط با
  کلید محیطی `SEMANTIC_SCHOLAR_API_KEY` (بدون کلید، شفاف رد می‌شود).
- **منابع فارسی:** با اسکریپت خودکار تأیید نمی‌شوند؛ مسیر بررسی، پروتکل تعاملی
  است: `docs/interactive_research_protocol.md`.
- **محدودیت مهم:** ابزارهای داخلی ایجنت (`web_search` / `fetch_page`) فقط در
  جلسهٔ تعاملی در دسترس‌اند و از پایتون فراخوانی نمی‌شوند؛ دسترسی آن‌ها در
  GitHub Actions تست/تأیید **نشده** و نباید فرض شود.

```bash
# اجرا نمونه (سه منبع آزمون)
python -m agents.researcher_cli \
  --input tests/fixtures/three_refs.json \
  --output data/processed/research_verification_v2.json \
  --report data/processed/research_verification_v2.md

# تست‌ها
python -m unittest discover -s tests
```

وضعیت‌های خروجی: `VERIFIED`، `VERIFIED_WITH_LIMITATION`، `METADATA_MISMATCH`،
`RELEVANCE_UNCLEAR`، `UNVERIFIED_ACCESS_LIMITATION`،
`NOT_FOUND_AFTER_MULTISOURCE_SEARCH`، `FABRICATION_SUSPECTED`.
نداشتن DOI به‌تنهایی هرگز به معنای جعلی بودن منبع نیست.

## ⚠️ هشدارهای آکادمیک

- 🎯 این ابزار صرفاً برای **کمک، ایده‌پردازی و تسهیل فرآیند** است؛ مسئولیت علمی و حقوقی نهایی محتوای پایان‌نامه با **دانشجو** است.
- 🔎 صحت منابع، استنادها، آمارها و ادعاهای علمی را **حتماً به‌صورت دستی** راستی‌آزمایی کنید؛ مدل‌های زبانی ممکن است منابع ساختگی (Hallucination) تولید کنند.
- 🏛️ بسیاری از دانشگاه‌ها استفاده از ابزارهای هوش مصنوعی بدون اعلام قبلی را مصداق **تخلف علمی** می‌دانند. پیش از استفاده، **قوانین دانشگاه خود را بررسی کنید** و در صورت لزوم، استفاده از این ابزار را به استاد راهنما اعلام نمایید.
- ✋ هیچ خروجی تولیدشده را بدون بازبینی و تأیید نهایی در پایان‌نامه قرار ندهید.
